# 技术文档 · SF Bay Weekly

## 1. 架构

```
┌─────────────────┐
│  编辑者（每周）   │  搜索 + 核实 + 补充社群渠道内容
└────────┬────────┘
         │ 追加写入
         ▼
┌─────────────────────────────┐
│  Google Sheet · Events 标签页 │  单一数据源（12 列 × N 行）
└────────┬────────────────────┘
         │ SpreadsheetApp.openById().getDataRange().getValues()
         ▼
┌─────────────────────────────────────────────────┐
│  Google Apps Script  (src/Code.gs)              │
│                                                 │
│   doGet(e) ──────────► 服务端渲染 HTML 字符串     │
│                        HtmlService 输出          │
│                                                 │
│   sendWeeklyEmail() ─► GmailApp.sendEmail()      │
│        ▲                                        │
│        │ 每周三 09:00                             │
│   ClockTriggerBuilder（由 createWeeklyTrigger 建）│
└──────┬──────────────────────────┬───────────────┘
       │ Web App 部署（版本化）      │ 触发器（跑 HEAD）
       ▼                          ▼
  公开网页 /exec              读者收件箱
```

**为什么是 Apps Script 而不是常规 Web 栈**

| 候选方案 | 否决原因 |
|---------|---------|
| Netlify / Vercel + 静态站 | 不支持持久化数据更新——每周更新内容要重新部署，且没有现成的定时发信能力 |
| 独立后端 + 数据库 | 对每周 20 条数据的场景严重过度设计；还要额外承担服务器与域名成本 |
| 第三方邮件服务（SendGrid 等） | 需要把收件人邮箱交给第三方；作者明确出于隐私考虑拒绝 |
| **Apps Script** ✅ | 零成本、零运维；Sheet 天然是编辑者能直接用的 CMS；发信走作者自己的 Google 账号，收件人地址不出 Google 生态；定时触发器内置 |

代价是被 Google 生态锁定，以及本地开发体验差（无本地运行时、无包管理）。
对这个规模的项目，这笔交易是划算的。

## 2. 代码结构（`src/Code.gs`，约 300 行，单文件）

```
CONFIG                    配置常量：SHEET_ID / 收件人数组 / 站点标题
├─ doGet(e)               Web App 入口，处理 ?week= 参数，默认最新一期
├─ readAllEvents_()       读 Sheet → 数组of对象，所有单元格过 cellToString_()
│   └─ cellToString_(v)   类型归一化：Date → 'yyyy-MM-dd'，其余 → trim 后的字符串
├─ getSortedWeekIds_()    去重 + 倒序，最新一期在前
├─ renderPage_()          组装完整 HTML 文档（侧边栏 + 主体）
│   ├─ formatWeekLabel_() '2026-09-02' → '09.02 那一周'
│   ├─ renderZone_()      按 Zone 过滤 → 按 SubGroup 分小节
│   └─ renderTicket_()    单条活动的车票 DOM
│       └─ esc_(v)        HTML 转义
├─ PAGE_CSS_              页面样式（模板字符串常量）
├─ sendWeeklyEmail()      取最新一期 → 精选优先取 5 条 → GmailApp 发信
└─ createWeeklyTrigger()  幂等地重建"每周三 9:00"触发器（先删同名再建）
```

### 2.1 服务端渲染，无前端框架

整个页面是在 Apps Script 里拼出来的一个 HTML 字符串，没有客户端 JS。
选择理由：内容是纯静态展示，数据量小（每期 ~20 条），
引入框架只会增加 iframe 内的加载时间——而 Apps Script 的 Web App 首屏本来就慢。

历史期次切换用的是普通链接 `?week=2026-08-26`，走完整的服务端往返，不做 SPA。

### 2.2 关键实现细节

**类型归一化 `cellToString_()`**

```javascript
function cellToString_(v) {
  if (v === null || v === undefined) return '';
  if (Object.prototype.toString.call(v) === '[object Date]') {
    return Utilities.formatDate(v, Session.getScriptTimeZone(), 'yyyy-MM-dd');
  }
  return String(v).trim();
}
```

Google Sheets 会把形如 `2026-09-02` 的输入自动识别成日期类型，
`getDataRange().getValues()` 返回的是 JS `Date` 对象。
早期版本直接对 `WeekId` 调 `.split('-')`，线上表现为整个页面 500。
现在所有单元格读取统一过这个函数，`Date` 用脚本时区格式化回字符串。

**HTML 转义 `esc_()`**

所有来自 Sheet 的内容在插入模板字符串前都过 `esc_()`（`& < > " '` 五个字符）。
`MapLink` 额外做协议白名单校验（`/^https?:\/\//i`），非链接内容不渲染 `<a>`。

**幂等的触发器创建**

```javascript
ScriptApp.getProjectTriggers().forEach(t => {
  if (t.getHandlerFunction() === 'sendWeeklyEmail') ScriptApp.deleteTrigger(t);
});
ScriptApp.newTrigger('sendWeeklyEmail').timeBased()
  .onWeekDay(ScriptApp.WeekDay.WEDNESDAY).atHour(9).create();
```

先清同名触发器再建，所以 `createWeeklyTrigger()` 可以安全地重复运行，不会累积出多个触发器。

### 2.3 CSS 设计约束

视觉是"车票存根"隐喻：`.ticket` 是 flex 容器，左边 `.stub` 用 `border-right: 2px dashed` 做撕票线。
配色取自旧金山的雾（`--fog: #c9d2d4`）和纸质车票（`--paper: #f2ecdc`），
字体用 Fraunces（衬线，标题）+ IBM Plex Mono（日期与地址，强调"票据感"）。

**踩过的坑**：侧边栏最初用 `position: sticky; height: 100vh`。
Apps Script 把用户 HTML 装进一个 iframe，而 iframe 的高度被撑到内容全高，
真正的滚动容器是外层页面——sticky 因此失效，`100vh` 还撑出大片空白。
改成普通流式布局解决。**在 Apps Script Web App 里，任何依赖视口的定位都要先验证。**

## 3. 数据层

见 [`data/schema.md`](../data/schema.md)。要点：

- 单一数据源就是一张 Sheet，没有数据库
- 12 列固定 schema，`WeekId` 做逻辑分区（不同 WeekId = 不同期）
- 没有主键、没有关联表——数据量不需要
- 每次 `doGet` 全量读表。当前 53 行，耗时可忽略；
  数据涨到几千行时需要改为按 `WeekId` 过滤后再读，或加缓存

## 4. 部署

两条**互不相同**的生效路径，是这个平台最容易搞错的地方：

| 改动内容 | 生效方式 |
|---------|---------|
| `sendWeeklyEmail()` 等触发器调用的逻辑 | **保存即生效**。触发器绑定的是 HEAD 版本 |
| `doGet()` / 渲染 / CSS | **必须发布新版本**：部署 → 管理部署 → 编辑 → 版本选「新版本」→ 部署 |

Web App 部署配置：
- 执行身份：**作者本人**（脚本需要以作者身份读 Sheet 和发信）
- 访问权限：**任何人**（读者不需要 Google 账号即可打开）

OAuth 授权范围：
- `spreadsheets`（读数据）
- `gmail.send` / `script.send_mail`（发信）
- `script.scriptapp`（创建触发器）——**这一项不在首次部署的授权范围内**，
  第一次运行 `createWeeklyTrigger()` 会因缺少它而失败，需要按错误提示补授权一次

## 5. 自动化编辑流水线

一个每周一触发的定时任务，携带完整上下文（资源链接、字段规则、验证方法论、边界约束），
在全新会话里执行 §功能文档 3.5 描述的五个步骤。

设计上的两个要点：

1. **提示词是"可执行的运行手册"**，不是概要。它包含具体的 URL、
   字段枚举值、踩坑提醒（例如"函数下拉框里 `sendWeeklyEmail` 就在 `createWeeklyTrigger` 上面一格，
   选错点运行会立刻发一封邮件出去"），因为每次触发都是无记忆的新会话。
2. **人的确认点是硬编码的**：OAuth 授权、Google 账号的「允许」按钮一律不代点；
   编辑者没回复就不编造内容，安静结束。

## 6. 安全与隐私

| 关注点 | 处理 |
|--------|------|
| 收件人邮箱 | 只存在于作者自己的 Apps Script 配置里，不经过任何第三方服务 |
| 网页公开性 | `/exec` 是无鉴权公开链接。内容只有公开活动信息，不含个人数据 |
| 公式注入 | 校验器拦截以 `=` `+` `@` 开头的单元格 |
| XSS | 所有 Sheet 内容经 `esc_()` 转义；`MapLink` 做协议白名单 |
| 仓库脱敏 | `src/Code.gs` 里的 Sheet ID 与收件人邮箱已替换为占位符；真实值不进版本库 |

## 7. 本地开发

Apps Script 没有本地运行时，但单文件是合法的 JavaScript，可以做语法检查：

```bash
cp src/Code.gs /tmp/Code.js && node --check /tmp/Code.js
python3 tests/validate_data.py data/sample_events.tsv
python3 tests/validate_data.py tests/fixtures_bad.tsv   # 回归用例，期望退出码 1
```

## 8. 后续改进方向

1. **渲染逻辑纯函数化** —— 把 `renderPage_` 及其下游改成不依赖 `SpreadsheetApp` 的纯函数，
   即可在 Node 里做快照测试，补上目前缺失的端到端覆盖
2. **邮件送达监控** —— 每周任务顺带读取 Apps Script 执行日志，发现触发器失败主动告警
3. **核实状态复查** —— 对标注为"已核实"的长期活动定期重新校验，避免信息过期
4. **`clasp` 接入** —— 用 Google 官方 CLI 做本地 ↔ Apps Script 的双向同步，
   让版本库成为唯一事实来源（目前是手工同步）
